## 0. 背景与决策记录（实现前必读）

### 0.1 问题来源

0.9.0（路径规则数据化 + 盖戳下发 + 替换排除）真机使用后，作者反馈 9 类问题。经源码审查 + bgd_sce_veri 实测定位，关键结论：

| # | 问题 | 定位结论 |
| --- | --- | --- |
| 1 | 替换排除「搞不清楚该填什么」 | 现行 `is_excluded` 只认带扩展名的完整相对路径或目录前缀，纯文件名永不命中 |
| 2 | 全量构建排除生效、监听增量不生效 | **实测确证**：watch 启动时 `cfg.clone()` 持快照，运行期间配置变更永不送达（GUI save_config / CLI config set 都不触达运行中监听；bgd.json 不在监听范围） |
| 3 | 多匹配支持 | 现行一行一条，无行内多匹配 |
| 4 | path_rules 被硬编码并进排除集 | `rules.rs effective_rewrite_excludes` 无条件 push `client/path_rules.lua`，设置里不可见不可删 |
| 5 | 路径基准不一致 | target/entrance 相对 `.bgd/`（`../ui/...`），res disk_prefix 相对项目根（`ui/...`），同卡片两种基准误导 |
| 6 | 希望注解跳过 | 新需求，定为**行级**（见 0.2 决策） |
| 7 | 每配置缺「恢复默认」 | 现仅 res_rules 行级有 |
| 8 | 残留硬编码 | 另查实 3 处：rewrite.rs 存在性检查写死 `.bgd/libs`/`.bgd/src`（改源码目录后检查失效，真 bug）；rewrite 前缀 `'libs'`/`'src'` 写死（merge.rs 却从 cfg 派生，口径撕裂）；盖戳 modules 键写死 |
| 9 | 整体审查 | 另发现 F3/F4/F5（见 WP-05） |

### 0.2 作者决策（2026-09-01 讨论定稿）

1. **路径基准**：全部统一为**相对项目根**；**不写迁移代码**（工具链仅作者自用），test_res002 配置手动更新。
2. **替换排除语义**：匹配**相对项目根的完整路径**（不含扩展名，可命中文件或目录），`|` 分隔多个，**不支持通配符**（准确、不误伤）。
3. **注解跳过**：定为**行级**——注解行的**下一行**跳过全部替换（require 改写 + res 替换），服务「同文件部分替换、个别行豁免」场景；文件级豁免已由 rewrite_excludes 覆盖，不做。
4. **配置热更新**：watch 内热重读（轮询 bgd.json mtime，不重启监听）。
5. **默认值收归工具自持**：`bgd_default.json` 随软件安装下发到**安装目录**（可见、随软件更新覆盖）；框架仓库的 `libs/bgd_default.json` 退役。
6. **性能结论**（讨论中已答作者问）：行级注解跳过 = 一次 memchr 级行扫产出跳过字节区间 + 替换闭包 offset 判定，增量微秒级、全量（544 文件）< 5ms；叠加 F4 性能债修复（正则预编译 + project_name 缓存）后全量构建**快于 0.9.0 现状**，无取舍问题。

## 2. 工作包明细

### WP-01 默认值收归工具：内嵌 bgd_default.json

**目标**：默认配置可见、随软件安装下发、随软件更新覆盖。

- tools 仓库根新增 `bgd_default.json` 为默认值唯一来源，Rust 侧 `include_str!` 内嵌。
- exe **入口早期**（main.rs，CLI/GUI 两条路径都执行）自检释放到**安装目录** `bgd_default.json`（幂等：内容一致跳过；升级后 exe 变 → 覆盖），模式参照 `ensure_path_registered`。**注意：加载永远走 exe 内嵌，释放出的文件只做「可见」，不作为配置层**（用户手改会被更新覆盖，不能当权威）。
- 加载链改为两层：**工具内建默认 → 项目 `.bgd/bgd.json` 覆盖**（overlay/save 只写差异的现状不变，差异对比基准从框架文件改为内建默认）。
- 默认值与现行框架 `bgd_default.json` 逐 key 对齐（行为零变化），并新增两个 key：
  - `rewrite_excludes: [".bgd/src/common/path_rules"]`——path_rules 保护从硬编码改为**可见默认**，可在设置中删除（UI 配警告文案：删除后盖戳将被替换损坏）。
  - `rewrite_skip_annotation: "-- @bgd:no-rewrite"`——注解文本可配置。
- `BgdConfig` 新增字段 `rewrite_skip_annotation: String`。
- 注意 save() 基准切换后，历史项目 bgd.json 中已存覆盖项不受影响（值不变即不新增差异）。

### WP-02 路径基准统一为相对项目根

| 配置 | 旧值（相对 .bgd） | 新值（相对项目根） |
| --- | --- | --- |
| libs_dir / game_dir | `libs` / `src` | `.bgd/libs` / `.bgd/src` |
| 四个 target | `../script/bgd_libs_server` 等 | `script/bgd_libs_server` 等 |
| 两个 entrance | `../src/main.lua` 等 | `src/main.lua` 等 |
| res disk_prefix | `ui/image/image/{prefix}` | 不变（本就是项目根） |
| libs_excludes / game_excludes / rewrite_excludes | 相对各 code set 源码根 | 相对项目根完整路径（如 `.bgd/libs/types`） |

- `cfg.abs()` 改为相对**项目根**（`bgd_root.parent()`）解析，保留 `..` 归一化与绝对路径兼容。
- 工具内建默认值同步改写为上述新值。
- **不写迁移代码**；test_res002 的 bgd.json 手动更新（WP-07）。

### WP-03 rewrite_excludes 新语义

- 条目 = **相对项目根的完整路径，不含扩展名**；命中文件（`a/b/c` 命中 `a/b/c.lua` 等任意扩展）或整个目录（`a/b` 命中 `a/b/...`）。
- `|` 分隔多个：一行可写 `.bgd/src/common/path_rules|.bgd/libs/client/legacy`；GUI 保持一行一条 + 行内可用 `|`。
- 不支持通配符。
- 匹配实现：条目按 `|` 拆分 → 归一化（`\`→`/`、去首尾 `/`、去扩展名）→ 与被测路径（同样归一化、去扩展名）做「相等或目录前缀」比较。
- **删除硬编码**：`effective_rewrite_excludes` 不再无条件并入 `PATH_RULES_REL`；保护完全交给 WP-01 的可见默认值。
- GUI hint 重写：明确「相对项目根完整路径、不含扩展名、可命中目录、| 分隔多个」+ 示例。

### WP-04 行级注解跳过

- 文件中某行含配置注解（默认 `-- @bgd:no-rewrite`，`rewrite_skip_annotation` 可配）时，其**下一行**跳过全部替换（require 改写 + res 路径替换）。
- 实现：`transform_and_write` 一次行扫产出跳过字节区间（有序数组）→ 传入 `rewrite_lua` / `rewrite_res_paths` 替换闭包，按 match 起点 offset 游标/二分判定。
- entrance 合并管线（`update_entrance` 的 rewrite_lua 调用）同样生效。
- 用法示例：

```lua
local a = require('libs.common.api.json')   -- 正常替换
-- @bgd:no-rewrite
local b = require('libs.keeper')            -- 此行保持原文
```
