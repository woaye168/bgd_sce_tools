## 1. 三仓库定位与协作关系

```
bgd_sce_tools（宿主，应用市场）
   │  读 registry.json（极简 id/name/repo）→ 各应用 Release 的 app-release.json 补全
   │  安装/升级/启动应用（--project-path / --background / --quit / notify project_path=）
   ▼
bgd_sce_appsdk（应用 SDK 仓库，双职责）
   ├─ registry.json          应用市场分发清单（当前 2 个应用）
   └─ Rust crate bgd_appsdk  公共基建：app（统一入口）/single_instance/watcher/ui/log/config
        ▲ crates.io 公开包 bgd_appsdk = "0.1"
        │（两个应用消费方式完全一致，均为 crates.io 版本依赖）
   ┌────┴─────────────────┐
sce_app_visual-injector   sce_app_editor-patch
模块To触编：扫描 .bgd      编辑器补丁：整库解密/插槽注入/补丁模块/
api/ Lua 模块 → 生成触编   C# MCP 桥（HttpListener + Gateway）/截图/
FunctionDefine/Class JSON  stdio MCP 聚合（编辑器控制唯一 MCP 入口）
+ SceInit.lua 注入
```

对 SDK 的依赖方式经核实：两应用 `Cargo.toml` 均为 `bgd_appsdk = "0.1"`（crates.io），`main()` 都收敛为一行 `bgd_appsdk::app::run(AppOptions{...})`，公共逻辑（CLI 分发/单实例/看守线程/窗口壳/日志/配置）零重复。editor-patch 因自身有 `mcp`/`editor`/`logs`/`capture`/`notify` 业务子命令，在进入 `app::run` 之前自行分发（`main.rs:38-53`），符合 SDK `lib.rs:13` 注释约定的「短进程 CLI 应在 acquire 之前分发」。

registry.json 设计与宿主 R5 清单读取链一致（极简条目，版本/描述由 app-release.json 补全），两应用条目完整（visual-injector / editor-patch）。

## 3. visual-injector 评估

| 文件 | 行数 | 职责 |
| --- | --- | --- |
| main.rs | 365 | UI（注入/设置/关于三标签页）+ 应用状态，入口一行 `app::run` |
| core.rs | 1315 | 扫描/解析/JSON 生成/SceInit 追加与移除（单一巨型文件） |

**Lua 解析健壮性**：解析器是「按行 + 前缀匹配 + 文档块累积」的启发式实现（`parse_function_line` core.rs:539、`parse_method_line` core.rs:679），只认 `function M.Xxx(`/`M:Xxx(`/`prototype:Xxx(` 形态，对 `M.x = function(...)`、local 函数、多行签名均不支持——与 AGENTS.md「模块写法统一 `local M = {} ... return M`」的框架约定自洽，属于「约定约束下的够用的解析」而非通用 Lua 解析。已知局限：
- `---@param` 类型按空白切分（core.rs:577-581），含空格的类型（如 `fun(a: number, b: number)`）会被截断为 `fun(a:`——恰好 `type_to_json` 用 `starts_with("fun(")` 判断（core.rs:961），仍能映射为 FuncType，只是签名信息丢失，属可接受退化。
- 事件过滤启发式 `On`+大写开头即剔除（core.rs:548），名为 `Online`、`Once` 类的合法函数会被误伤（低概率）。
- 多返回值只取第一个（`func.returns[0]`，core.rs:813）。

**JSON 生成正确性**：对照 AGENTS.md「常见坑」清单逐一核实——`label:"默认"`（core.rs:841）、`flags.fromOop`（:818）、restParameter 带 id（:865-903）、类名 `__bgd_` 前缀三处一致（SceInit 行 core.rs:229/256、JSON name :838/:1096、JSON id :840/:1097）、构造参数取 `M.New`（:652-660）——八个坑全部在代码层固化，且与 doc/visual_injection_spec.md 的结构描述一致。ENGINE_CLASSES 27 个引擎类型映射、用户类经 `---@class` 全量预扫描（register_modules core.rs:183-195）两趟解析，设计合理。

**SceInit 追加/移除幂等性**：追加按「去空白行内容」集合去重（core.rs:272-275），重复注册不产生重复行；移除按 `<pkg>.__bgd_src_`/`<pkg>.__bgd_libs_` 前缀过滤（core.rs:359-362），与生成行前缀严格同源，幂等性成立。瑕疵：移除后残留的 pkg 声明行与 AUTO-GENERATED 头不清理（卸载后留下只剩声明的空壳文件，无害但不干净）。

**其他**：`core.rs` 1315 行单文件（本仓库无 500 行约定，但函数/类解析与 JSON 生成两块已具备拆分条件）；随机 id 每次注册重新生成（见问题 L14）。

## 5. 优点清单

1. **SDK 抽象真消除重复**：两应用 main() 均一行 `app::run`（visual-injector main.rs:21-34、editor-patch main.rs:55-67），单实例/看守线程/日志/配置零重复实现。
2. **看守线程方案的实测结论沉淀**：watcher.rs:1-4、ui.rs:71-73 等注释把「egui 隐藏休眠→ViewportCommand 不可靠→Win32 直接驱动」的决策链写死在代码旁。
3. **editor-patch 集成测试质量**：kernel.rs:661-860（整库应用/还原字节一致 + 运行时注入回退）、bridge_deploy.rs:251-353（deploy/undeploy/restore 幂等 + 跨版本清理）、ENV_LOCK 防并发互踩（kernel.rs:666）。
4. **插槽复用判定的严谨性**：manifest 记录官方源 sha256，复用前逐文件比对新版本解码源（kernel.rs:138-154），杜绝「差不多就复用」。
5. **Gateway 自愈反馈**：invoke 参数错误内嵌 compact schema（Gateway.cs:34-44），AI 下一轮可自我修正——面向 AI 调用方的针对性设计。
6. **审计日志的反压取舍**：AuditLog.cs 有界 Channel + DropWrite，「审计可丢、主流程绝不阻塞」的取舍有明确注释。
7. **端口保留段处理**：McpServer.cs:107-153 探测 netsh 保留端口段并避让——Hyper-V/WSL 环境的真实坑，文档与代码双落地（main.rs:742 设置页提示）。
8. **弹窗抑制代数令牌**：bgd_mcp_bridge/main.lua:70、181-199 用 suppress_gen 防旧超时回调误关新抑制，细节到位。
9. **visual-injector 八坑全固化**：AGENTS.md「常见坑」逐条在 core.rs 有对应实现（见 §3）。
10. **editor.rs 日志工具链**：read_tail 尾部窗口读 + 64KB 上限（editor.rs:302-307/343-367）防 AI 上下文爆炸，get_game_logs 默认只返回文件信息的设计（mcp.rs:132 描述）体现对 LLM 消费场景的理解。

## 8. 总体结论

三个仓库整体质量显著高于一般个人项目：appsdk 的抽象真实消除了重复（两应用 main 均一行接入），editor-patch 的补丁链路（备份/幂等/字节级还原/三级回退）有集成测试逐字节守护，C# MCP 桥的 Gateway 架构（自愈 schema、安全分级、审计反压取舍）展现出对 AI 调用方场景的深入理解。未发现高危问题；中等级别集中在六处：write_atomic 并非真原子（与最高优先级红线的表述有差距）、strip_json_comments 的 UTF-8 字节缺陷、panic hook 硬编码用户路径、两个超 500 行约定的大文件、pie_capture 在非 169 版本静默失效、MCP 桥本机无鉴权。偏差主要是「文档/注释滞后于实现」一类（D2/D3/D4/D7），其中 visual-injector 的注入规范文档 SceInit 路径描述已过期，建议优先修正以免误导后续改动。建议优先处理 M1/M2/M5 三个有实际正确性影响的问题，其余多为低成本清理项。
