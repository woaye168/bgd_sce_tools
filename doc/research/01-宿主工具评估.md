## 3. 优点清单（设计得当之处）

1. **CLI 与 GUI 共享同一代码路径**（cli.rs:8, main.rs:18-23）：CLI 子命令直接调用 `builder::build_all` / `project::update_framework` 等核心函数，"测 CLI 就是测真实产物"的约定在代码层面成立；release 下 `AttachConsole` 处理 windows 子系统 stdout 吞没问题（main.rs:8-14），细节到位。
2. **token 传输安全做对了**（net.rs:21-23, 88-91）：`HeaderValue::set_sensitive(true)` + reqwest 跨主机重定向自动剥离 Authorization，私有 asset 302 到 CDN 不泄露 token；统一走 `http_client`/`async_http_client` 两个工厂，无绕过。
3. **私有仓库 asset 下载路径正确**（apps.rs:314-327, updater.rs:83-95）：一律走 `repos/<repo>/releases/...` API 定位 asset → `asset.url` + `Accept: application/octet-stream`，规避了私有仓库直链 404 的坑。
4. **配置 overlay 保存只写差异**（config.rs:83-110）：`STATE_KEYS` 状态字段与覆盖项分离，bgd.json 保持最小化，框架更新下发新默认值不会被项目旧覆盖钉死。
5. **三路哈希更新考虑周全**（project.rs:219-230, 425-496）：文本统一 LF 后哈希防 CRLF 误报；冲突保留本地 + 另存 `.framework-new`；无基准时下载旧版 tag 重建基准，重建失败降级保守模式（只增不删不覆盖）——失败路径都有明确语义。
6. **入口合并自愈**（builder.rs:585-603）："原文仍含标记"判定为脏数据并丢弃重建，一次构建自愈，防御性设计合理。
7. **监听去重以文件实际存在性为准**（builder.rs:1018-1021）：去重窗口结束时用 `path.exists()` 复核删除态，避免编辑器原子保存（删+建）造成误删产物。
8. **Tauri capabilities 权限面最小**（capabilities/default.json）：仅 `core:default` + `dialog:default`，无 shell/fs/http 插件权限，前端攻击面小。
9. **版本号单一来源**：源码三处固定 `0.0.0-dev`，release.yml 构建前从 git tag 注入 tauri.conf.json + Cargo.toml，杜绝手工同步漂移（AboutPage 用 `getVersion()` 运行时读取）。
10. **zip 解压安全**：zip 2.x `archive.extract` 默认走 `enclosed_name` 路径穿越防护（project.rs:136），框架包解压无 Zip Slip 风险。

## 6. 总体结论

bgd_sce_tools 整体是一份**工程质量高于平均水平的宿主工具代码**：CLI/GUI 同路径、token 敏感头处理、三路哈希更新的失败降级、入口合并自愈等关键机制都经过实战打磨，注释密度与"已踩坑"记录尤其出色，Tauri 权限面也收得很紧。最需要立即修复的是两个确定性 bug：**自我更新下载 URL 缺 owner 必然 404（H1）** 与 **CLI 死命令触发 unreachable!() panic（H2）**，二者都在真实用户路径上。中期欠账集中在 builder.rs 的职责过载（1030 行）、github_token 明文存储、以及同步/async 双份实现遗留的死代码。AGENTS.md 与实际代码的偏差共 7 条，多为文档滞后于机制演进（版本号注入、app 子命令、CLI watch 状态文件），建议在下一轮迭代中按 D1-D7 逐条核对修订。前后端契约总体健康，仅 types.ts 残留 3 个幻影字段需要清理。
